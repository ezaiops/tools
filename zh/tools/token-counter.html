成本是怎么算的

    
所有厂商都按 token 计费。文本先转换为词元——GPT 系列使用与 OpenAI 生产环境相同的字节对编码分词器，计数与 API 回报一致。成本 = (输入 tokens ÷ 1,000,000) × 输入价 + (输出 tokens ÷ 1,000,000) × 输出价，取各厂商目录价。月度投射 = 单次成本 × 每日请求量 × 30 天。

    
真实账单由两个失真主导：输出 token 按输入价的 2–8 倍计费；agent 和思维链负载输出占比高。真正能砍账单的三个杠杆：Batch API（通常五折）、prompt 缓存（命中价约为输入基础价的 10%——对重复语料的 RAG 是决定性因素）、以及选对模型档位——把 80% 的简单流量分流到 mini 或 flash 档，通常是最大的单项节省。


    
降低 LLM 账单的技巧

    
    
      
  • Batch API 五折。OpenAI、Anthropic 和 Google 都对异步批量负载的输入输出价格减半——适合夜间富化或批量分类。
    • 
      
  • prompt 缓存。Anthropic Claude 的缓存命中可把输入成本降到基准的约 10%；Gemini 上下文缓存对重复上下文通常省 80–90%。
    • 
      
  • 选对模型档位。路由、抽取或摘要类任务，Luna/Haiku/Flash 级调用通常比旗舰便宜 5–20 倍——决定前先用上表测算切换效果。
    • 
      
  • 控制输出长度。设置 max-token 上限；失控的补全是意外账单最常见的来源。
    • 
    


    
常见问题

    

      分词数量准确吗？
      
OpenAI GPT 系列模型精确（cl100k_base / o200k_base）。Claude、Gemini、Grok 和 DeepSeek 为接近的近似值——这些厂商使用不同的分词器，且并未全部公开。

    

    

      我的 prompt 会离开浏览器吗？
      
不会。分词与成本计算都在你设备的 JavaScript 中进行，工具不会用你的内容发任何网络请求。

    

    

      月度估算是怎么算的？
      
单次成本 × 每日请求量 × 30。单次成本使用你输入的输入/输出 token 数；启用 Batch 时两侧价格同时减半，缓存命中率按模型缓存价混入输入价。每次请求的 token 数超过厂商阈值时，长上下文档位自动切换。

    

    

      这些是官方价格吗？
      
表中数据编译自各厂商官方定价文档，并与聚合站交叉核对。价格变动频繁——重大预算决策前请以厂商官方信息为准。
