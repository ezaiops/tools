每行粘贴一个 CIDR 块。检测器会两两比较，报告每一处冲突以及精确的共享地址范围——在重叠的 VPC、VLAN 或 VPN 地址池引发路由问题之前，这是最快的排查方式。

子网计算原理

    
IPv4 地址是 32 位，写成四段。前缀长度——斜杠后面那个数字——表示前多少位属于网络。网络地址保留这些位、其余置 0；广播地址把主机位全置 1。两者之间（去掉两端保留）就是可分配的主机地址，所以 /24 有 254 个可用地址，/30 有 2 个——经典的点对点链路。

    
有两个细节容易踩坑：可用主机数是 2^(32-prefix) − 2，但 /31 例外（RFC 3021，点对点链路两个地址都可用），/32 也只有单个主机。另外像 192.168.1.37/26 这样的主机地址，其实属于网络 192.168.1.0/26——计算器总是显示该地址所属的网络。


    
CIDR 记法、掩码与通配符掩码

    
同一条边界有三种写法。CIDR 记法数的是网络位数：/26。点分掩码把这些位写成一个地址：255.255.255.192。通配符掩码则把每一位取反：0.0.0.63。三者互转纯是算术——数前导 1 得到前缀，取反得到通配符——所以上面的计算器一次显示三种，而不要求你先选一种格式。

    
真正出事的是通配符。思科风格的 ACL 和 OSPF 的 network 语句要的是通配符而不是掩码，把 255.255.255.0 填在应该是 0.0.0.255 的位置，会静默匹配到错误的流量。如果某条规则的效果正好和你想要的相反，先查这个是不是写反了。


    
在 AWS VPC 和其他云上规划子网

    
一个 VPC 由一个 IPv4 CIDR 块定义，里面每个子网都必须从这块里切出来。AWS 接受 /16 到 /28 之间的块，所以实际遇到的问题永远是“我的 VPC 能装下多少个多大的子网”——这正是上面切分器回答的。一个 /16 的 VPC 可以容纳 256 个 /24 子网；常见做法是每个可用区、每一层各用一个 /24。

    
最费时间的故障是网段重叠：两个 VPC 之间、VPC 与本地机房之间、或者 VPC 与 VPN 地址池之间共用了地址。对等连接和 Transit Gateway 都拒绝在重叠范围之间路由，而报错点往往离真正的原因很远。创建任何东西之前，先把规划好的块粘进重叠检测——十秒钟的事，能省一次重建。


    
切分网络，以及 VLSM 到底是什么

    
等分是简单的情况：前缀加一位，子网数翻倍、主机数减半。/24 → 两个 /25 → 四个 /26，以此类推。上面的计算器对任何块最多可以切到 64 个子网。

    
VLSM（变长子网掩码）说的是各子网不等长的情况——服务器用 /26，负载均衡器用 /28，每条点对点链路用 /30。让它成立的规则很简单：先分配最大的段，放在最低的对齐地址上，然后用剩下的继续分。顺序反了就会把地址空间切碎、浪费地址。只需要等分的话，用切分器就够了；如果是在设计真实的地址规划，先按每层的主机数向上取到 2 的幂，再从大到小往下排。


    
为什么这个计算器只支持 IPv4

    
IPv6 用 128 位地址，而且没有广播地址，所以这里的算术——网络地址、广播地址、可用范围、2^(32−prefix) − 2——都套不过去。IPv6 的标准子网是 /64，里面有 2^64 个地址，算“可用主机数”没有意义。如果需要 IPv6 的前缀计算，把前缀当成单纯的位边界处理、完全跳过广播地址那一步即可。


    
常见问题

    

      一个 /24 有多少个可用主机？
      
254 个。一个 /24 有 256 个地址，网络地址和广播地址各占一个，所以 256 − 2 = 254 个可分配。/25 是 126 个，/26 是 62 个，/27 是 30 个，/28 是 14 个，/29 是 6 个，/30 是 2 个。

    

    

      怎么把 IP 范围转成 CIDR？
      
在上面的“IP 范围转 CIDR”里填入起始和结束地址。它返回恰好覆盖这个范围的最小块集合——例如 192.168.1.10–192.168.1.100 会变成几个 /31、/30、/29 块，而不是一个过大的 /24。凡是无法用单个块表达的，都会拆成数量最少、能装下的那些块。

    

    

      怎么检查两个子网是否重叠？
      
当一个块的起点落在另一个块的范围内时，两者就重叠：A.network ≤ B.broadcast 且 B.network ≤ A.broadcast。重叠检测会对每一对都做这个比较，包含包含关系——一个 /25 落在 /24 里面也算重叠，因为两者无法独立路由。

    

    

      为什么 /31 和 /32 不减两个主机？
      
它们是特例：/31 由 RFC 3021 定义，用于两个地址都可用的点对点链路；/32 是单主机路由（环回或主机防火墙条目）。其余都遵循 2^(32−前缀) − 2。

    

    

      最小能用多大的子网？
      
普通广播网络上最小是 /30——两个可用地址。按 RFC 3021，/31 可用在点对点链路上；/32 标识单个主机。AWS 的 VPC 子网最小到 /28（16 个地址，AWS 保留 5 个后剩 11 个可用）。

    

    

      我的地址会被发送出去吗？
      
不会。所有计算都在你的浏览器中用 JavaScript 整数运算完成，没有任何传输。页面加载完之后，整页离线也能用。
