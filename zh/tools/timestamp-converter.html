一段话看懂 Unix 时间

Unix 纪元指自 1970 年 1 月 1 日 00:00:00 UTC 以来经过的秒数（不含闰秒——Unix 时间假装每天正好 86,400 秒）。毫秒时间戳是同一计数值乘以 1,000，也就是 JavaScript 的 Date.now() 和大多数 JSON API 的返回格式。因此时间戳 0 即纪元本身，负值则是 1970 年之前的时刻。

常见时间戳坑

  • 秒与毫秒混淆。10 位时间戳是秒，13 位是毫秒。混用是最高发的时间戳 bug——13 位的值会溢出 32 位整数，弄坏某些数据库。
  • 秒级精度存储。像 1728790800.123 这样的浮点在许多引擎中会被悄悄丢掉亚秒精度。
  • 2038 年问题。32 位有符号秒数将在 2038 年 1 月 19 日溢出。请使用 64 位存储或毫秒。
  • 服务器时区不是你的时区。用 UTC 存储和计算，在边缘格式化；永远不要用恰好运行你代码的那台虚机的时区去格式化时间戳。

常见问题

时间戳的最大值是多少？
JavaScript 日期在纪元附近 ±8,640,000,000,000,000 毫秒（约 ±273,790 年）范围内可靠，远超任何实际用途。64 位系统有相近的上限。
闰秒会被计入吗？
不会。Unix 时间忽略闰秒；每插入一个闰秒，UTC 与 Unix 时钟就相差一秒，之后重新同步。对日志场景来说这个差异不可见。
时间戳会被发送到别处吗？
不会。所有转换都在你的浏览器中用内置 Date 对象完成。
