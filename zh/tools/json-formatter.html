这个 JSON 格式化工具能做什么

    
格式化（也称美化）用一致的缩进重新序列化文档，让深层嵌套的 API 响应变得可读。压缩则相反——去掉所有非必需空白，适合在线传输负载或嵌入配置文件。

    
校验严格按照 JSON 规范（RFC 8259）解析文档，并报告第一处问题的精确位置：行号、列号以及解析器本身的报错。这一个位置通常就足以定位尾随逗号、未转义引号或括号不匹配。


    
常见 JSON 错误及含义

    
    
      
  • 尾随逗号——{"a": 1,} 是无效 JSON，尽管在 JavaScript 对象中合法。
    • 
      
  • 单引号——JSON 字符串必须用双引号，{'a': 1} 会报错。
    • 
      
  • 注释——严格 JSON 不允许 // 和 /* */（配置里需要注释就用 JSONC）。
    • 
      
  • 未加引号的键——{a: 1} 会失败，键必须是字符串。
    • 
      
  • NaN / Infinity / undefined——JSON 中都不存在，请用 null 或字符串。
    • 
    


    
常见问题

    

      有大小限制吗？
      
唯一限制是你浏览器的内存。几 MB 的文档也能瞬间格式化，因为一切都发生在你的设备上，没有上传环节。

    

    

      我的 JSON 会被上传吗？
      
不会。解析、格式化和校验都由浏览器内置的 JSON.parse / JSON.stringify 完成，不会有任何传输。

    

    

      为什么格式化后键的顺序变了？
      
不会——JSON.stringify 保持插入顺序。如果顺序变了，说明输入里有重复键，解析器保留了最后一次出现的值，与 JSON.parse 的行为一致。
