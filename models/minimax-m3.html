How to think about MiniMax M3 pricing

Output tokens bill at 4.0× the input rate, which is the number that decides whether a workload is affordable: summarization and classification are input-heavy, while agents, chain-of-thought reasoning and long-form drafting are output-heavy. Before comparing headline prices, measure the real token mix from your own logs, then apply the blended formula (input share × input price) + (output share × output price).

Beyond the headline rate, three levers usually decide a real bill: batch discounts where the provider offers one, cache hits on a stable prompt prefix, and right-sizing — routing simple steps to a mini or flash-class model instead of the flagship. Not every provider offers all three, so confirm which apply rather than assuming them. A cache hit bills at $0.06 against $0.30 for a miss, so a reused prefix is the cheapest tokens you will ever buy.

Frequently asked questions

How much does MiniMax M3 cost per 1M tokens?
$0.30 per 1M input tokens, $1.20 per 1M output tokens Cached input is billed at $0.06 per 1M tokens where caching is supported.
Does the MiniMax M3 context window cost extra?
Long prompts above 512,000 tokens switch to the higher tier ($0.60 in / $2.40 out). Below that the rate is flat.
What is the cheapest way to run MiniMax M3 at scale?
Keep a stable prompt prefix so it caches; cached input runs at $0.06 per 1M, cap output length, schedule asynchronous work into off-peak windows where the provider prices by time, and move the easy 80% of traffic to a lower tier.
