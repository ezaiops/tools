How the break-even math works

    
Self-hosting has roughly fixed cost (GPU-hours × rate) and effectively zero marginal cost per token; APIs are pure marginal cost (tokens × price). The break-even is where the two lines cross:

    
break-even tokens = GPU monthly cost ÷ API price per token

    
The catch is utilization: a 24×7 GPU burns money whether or not requests arrive, so below the break-even you are strictly worse off, and near it you carry ops risk (SLA, upgrades, security patches) that an API absorbs. Above it — typically hundreds of millions of tokens per month — the GPU wins, often by 3–10×. For most teams the honest answer is: start on the API, move the stable high-volume slice to self-hosting once it clearly exceeds break-even, and keep the API as the burst fallback.

    
Model quality is the other half of the equation — this tool compares cost only. A 70B open model is not a GPT-6-class model; the fair comparison is usually an open model against a cheaper API tier (see the pricing table).


    
Frequently asked questions

    

      Are the GPU rates realistic?
      
They are typical on-demand cloud rates for single GPUs (RunPod, Lambda, Vast.ai class). Reserved or spot pricing goes lower; enterprise on-demand goes higher. Set your own with "Custom…".

    

    

      What throughput should I assume?
      
A single 4090 serving an 8B model with vLLM does roughly 2,000–4,000 output tok/s; a 70B model on 2×A100 is in the 5,000–15,000 range for short contexts. Long contexts and batching change both numbers — measure with your own workload.

    

    

      Does this include engineering time?
      
No — only compute. Running your own inference stack means ops work (deployment, monitoring, upgrades, on-call). As a rule of thumb, add a full-time engineer's amortized cost if you go self-hosted; the calculator's verdict assumes you already have that capacity.
