What this JSON formatter does

    
Formatting (also called beautifying) re-serializes your document with consistent indentation, which makes deeply nested API responses readable. Minifying does the opposite — it strips all optional whitespace, which is what you want when shipping payloads over the wire or embedding data in a config file.

    
Validation parses the document strictly according to the JSON spec (RFC 8259) and reports the precise location of the first problem: the line, the column, and the parser's own message. That single position is usually enough to spot a trailing comma, an unescaped quote or a mismatched bracket.


    
Common JSON errors and what they mean

    
    
      
  • Trailing commas — {"a": 1,} is invalid JSON, though legal in JavaScript objects.
    • 
      
  • Single quotes — JSON strings require double quotes; {'a': 1} fails.
    • 
      
  • Comments — // and /* */ are not allowed in strict JSON (use JSONC if you need comments in config).
    • 
      
  • Unquoted keys — {a: 1} fails; keys must be strings.
    • 
      
  • NaN / Infinity / undefined — none exist in JSON; use null or a string.

Frequently asked questions

    

      Is there a size limit?
      
The only limit is your browser's memory. Documents of several megabytes format instantly because everything happens on your device with no upload step.

    

    

      Is my JSON uploaded anywhere?
      
No. Parsing, formatting and validation are done with the browser's built-in JSON.parse / JSON.stringify. Nothing is transmitted.

    

    

      Why does the formatted output reorder my keys?
      
It doesn't — JSON.stringify preserves insertion order. If order changed, the input had duplicate keys and the parser kept the last occurrence, exactly as JSON.parse does.
