Encoding notes

  • Base64 turns binary or UTF-8 text into ASCII using a 64-character alphabet. Encoding is UTF-8 safe here, so CJK text and emoji round-trip correctly.
  • URL encoding percent-encodes characters that are not allowed in URLs. "Component" mode (encodeURIComponent) escapes more aggressively — use it for query parameter values, not whole URLs.
  • HTML entities prevent injection: & for &, < for < and so on.
  • SHA-256 is computed by a built-in implementation in JavaScript, so it works everywhere. SHA-1/384/512 use the browser's native crypto.subtle, which requires a secure context (https:// or localhost) — and SHA-1 is cryptographically broken, use it only for legacy checksums.

Frequently asked questions

Why does Base64 encoding make my file bigger?
Base64 encodes 3 bytes as 4 characters, so output is about 33% larger. That is the cost of being able to carry binary data over text-only channels (JSON, URLs, email).
Are my inputs uploaded?
No. Every conversion runs locally. Nothing is transmitted.
Base64 or hex for tokens?
Hex is more common for hashes (it is what most checksum tools output); Base64 is more compact. This page outputs hex by default for hashes and can switch to Base64.
