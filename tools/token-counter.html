How the cost calculation works

    
Every provider bills by the token. Your text is first converted into tokens — for GPT-family models this uses the same byte-pair-encoding tokenizer OpenAI serves in production, so the count matches what the API reports. Cost is then (input tokens ÷ 1,000,000) × input price + (output tokens ÷ 1,000,000) × output price, using each provider's list price. The monthly projection multiplies that per-request cost by your daily volume and 30 days.

    
Two distortions dominate real bills: output tokens are billed at 2–8× the input rate, and agentic or chain-of-thought workloads are output-heavy. The three levers that actually cut a bill are the batch API (typically 50% off), prompt caching (cache hits often cost around 10% of the base input rate — decisive for RAG with a repeated corpus), and right-sizing the model — routing the easy 80% of traffic to a mini or flash tier is usually the largest single saving.


    
Tips to cut your LLM bill

    
    
      
  • Batch APIs cut 50%. OpenAI, Anthropic and Google all halve input and output prices for asynchronous batch workloads — ideal for nightly enrichment or bulk classification.
    • 
      
  • Prompt caching. A cache hit on Anthropic Claude can drop input cost to roughly 10% of base; Gemini context caching typically saves 80–90% on repeated context.
    • 
      
  • Right-size the model. A Luna/Haiku/Flash-class call is often 5–20× cheaper than the flagship for routing, extraction or summarization — model the swap in the table above before deciding.
    • 
      
  • Watch output length. Set a max-token limit; runaway completions are the most common source of surprise bills.

Frequently asked questions

    

      How accurate is the token count?
      
Exact for OpenAI GPT-family models (cl100k_base / o200k_base). For Claude, Gemini, Grok and DeepSeek it is a close approximation — those vendors use different tokenizers and do not publish them all.

    

    

      Does my prompt leave my browser?
      
No. Tokenization and cost calculation happen in JavaScript on your device. The tool makes no network requests with your content.

    

    

      How is the monthly estimate computed?
      
Per-request cost × requests per day × 30. Per-request cost uses the input/output tokens you entered, with the batch discount applied to both rates when enabled and the cache-hit ratio mixed into the input rate using the model's cached price. Long-context tiers switch automatically when tokens per request cross a provider's threshold.

    

    

      Are these the official prices?
      
The table is compiled from each provider's official pricing documentation and cross-checked against aggregators. Rates change frequently — always confirm against the provider before committing budget.
